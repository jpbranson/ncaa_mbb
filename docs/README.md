# docs/

Nine documents. Which one you want depends on why you are here.

| Start here if you want to… | Read |
|---|---|
| understand the model | `cbbwp-EXPLAIN.md` |
| pick the work back up | `cbbwp-progress-and-results.md` |
| know what is frozen and what a change must beat | `cbbwp-CHECKPOINT.md` |
| run it live | `cbbwp-deployment.md` |

## Every file

| File | What it is |
|---|---|
| `cbbwp-EXPLAIN.md` | **The whole model in plain language.** A glossary of every mathematical term, every decision with the alternative that was rejected, the known weaknesses, and a Q&A. Written to be presented from. |
| `cbbwp-progress-and-results.md` | Build log, current results, what to do next. The re-entry point for a fresh session. |
| `cbbwp-CHECKPOINT.md` | What is frozen at `checkpoint-2026-09-02`: shas, scores, and the five things a future change has to do to count as an improvement. |
| `cbbwp-deployment.md` | The run book. The smoke test, the Mac and container paths, the two-step ratings refresh, how to swap models, what to check when something looks wrong. |
| `cbbwp-endgame-plan.md` | The endgame simulator's **pre-registration**: the bar it had to clear, written before any of it existed. **Do not edit this file.** Its value is entirely that it predates the result. |
| `cbbwp-endgame-phase2.md` | The measured endgame parameters, and the free-throw censoring artifact that had to be understood before any of them were trustworthy. |
| `cbbwp-endgame-results.md` | The table, the single-shot test, and the verdict: four of five criteria passed, so it does not ship. |
| `cbb-win-probability-model-plan.md` | The original design plan, kept verbatim. Where the build departed from it, EXPLAIN §7 says why. |
| `cbbwp-source.md` | Every source file in one document, for disaster recovery. **Generated — do not edit by hand.** |

## Mirrored to the Claude project

All of the above are mirrored into the project (`claude/…`) so a fresh session
can read them without the folder mounted. **This folder is the source of
truth**; the project copies are the mirror. When you change a doc here, push it
there.

Two project docs are *not* mirrored down here: `cbbwp-report-page.md` and
`cbbwp-report-data.md`. They are the source of the published results artifact
rather than working files, and the artifact is updated from the project.
`scripts/evaluate.py` regenerates every number in them.

## Regenerating the source bundle

```bash
python3 scripts/build_source_bundle.py
```

It walks `src/`, `scripts/` and `tests/`, stamps the commit it was built from,
and writes `cbbwp-source.md`. This used to be an inline snippet pasted into this
README, which is exactly why the bundle had quietly fallen three files behind
the code before anyone noticed.

**Keep EXPLAIN.md current.** When a number changes, change it there too — it is
the document people will actually read.
